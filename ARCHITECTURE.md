# Архітектура Проєкту "CourseWork_GameEngine"

Цей документ описує архітектуру ігрового рушія та прикладу гри, розроблених у рамках курсової роботи. Проєкт складається з двох основних частин: `cw_engine` (ядро рушія) та `cw_game` (клієнтська гра, що використовує рушій).

---

## 1. Загальний Огляд Проєкту

Проєкт реалізує базовий 2D-ігровий рушій, який надає функціональність для:
*   Управління вікном та вводом.
*   2D-рендерингу (спрайти, камери).
*   Системи сутностей-компонентів (ECS) для організації ігрових об'єктів.
*   Базової 2D-фізики (гравітація, колізії).

Клієнтська частина (`cw_game`) демонструє використання рушія для створення простого платформера.

## 3. Основні Компоненти Рушія та Шаблони Проектування

Проєкт активно використовує **Entity-Component-System (ECS)** шаблон проектування, що дозволяє гнучко створювати ігрові об'єкти та керувати їхньою поведінкою.

### 3.1. `Engine::Application` (EngineCore/Application.h)
*   **Призначення**: Базовий клас для всієї ігрової програми.
*   **Відповідальність**:
    *   Ініціалізація та керування вікном (`Window`).
    *   Запуск та підтримка основного ігрового циклу (`Run()` метод).
    *   Виклик методів оновлення (`OnUpdate()`) та рендерингу (`OnRender()`) на кожному кадрі.
*   **Використання**: Клієнтська гра (`GameApp`) успадковує цей клас та реалізує його чисто віртуальні методи для визначення ігрової логіки та рендерингу.

### 3.2. `Engine::Scene::Scene` (Scene/Scene.h)
*   **Призначення**: Контейнер для всіх `GameObject` на поточному рівні або екрані.
*   **Відповідальність**:
    *   Володіння та керування життєвим циклом `GameObject` (створення, видалення).
    *   Централізований виклик `OnUpdate()` та `OnRender()` для всіх своїх `GameObject`.
    *   Надання методів для пошуку `GameObject` за іменем.
*   **Використання**: `GameApp` створює екземпляр `Scene` і додає до нього всі ігрові об'єкти рівня.

### 3.3. `Engine::Scene::GameObject` (Scene/GameObject.h)
*   **Призначення**: Основна сутність у сцені, що представляє будь-який об'єкт у грі.
*   **Відповідальність**:
    *   Зберігання базових трансформаційних даних: `Position`, `Rotation`, `Scale`.
    *   Зберігання списку `Component`, які визначають його поведінку та вигляд.
    *   Надання методів для додавання (`AddComponent<T>()`) та отримання (`GetComponent<T>()`) компонентів.
    *   Делегування викликів `OnUpdate()` та `OnRender()` своїм компонентам.
*   **Принцип ECS**: `GameObject` сам по собі "порожній" і не має жодної поведінки. Вся його функціональність визначається компонентами, які до нього прикріплені.

### 3.4. `Engine::Scene::Component` (Scene/Component.h)
*   **Призначення**: Базовий клас для всіх компонентів, що розширюють функціональність `GameObject`.
*   **Відповідальність**:
    *   Надання віртуальних методів життєвого циклу: `OnStart()`, `OnUpdate(float dt)`, `OnRender()`.
    *   Зберігання посилання на `GameObject`-власника (`m_Owner`).
*   **Використання**: Конкретні компоненти (наприклад, `SpriteRenderer`, `RigidBody2D`, `PlayerController`) успадковують цей клас та реалізують його методи для додавання специфічної поведінки.

## 4. Фізична Система (Physics/)

Фізична система реалізована за допомогою двох основних компонентів:

### 4.1. `Engine::Physics::RigidBody2D` (Physics/RigidBody2D.h)
*   **Призначення**: Надає об'єкту фізичні властивості та керує його рухом.
*   **Відповідальність**:
    *   Зберігання `Velocity` (швидкості).
    *   Застосування `GRAVITY` (гравітації) з можливістю масштабування (`GravityScale`).
    *   **Виявлення та вирішення колізій**: Обчислює потенційну наступну позицію, перевіряє перетини з іншими `BoxCollider2D` та коригує швидкість/позицію, щоб уникнути проникнення. Це вирішує проблему "сипучих пісків".
*   **Використання**: Додається до `GameObject`, який повинен взаємодіяти з фізикою (падати, зіштовхуватися).

### 4.2. `Engine::Physics::BoxCollider2D` (Physics/BoxCollider2D.h)
*   **Призначення**: Визначає прямокутну область для виявлення зіткнень.
*   **Відповідальність**:
    *   Зберігання `Size` та `Offset` колайдера.
    *   Надання методу `GetAABB()` для отримання Axis-Aligned Bounding Box у світових координатах.
    *   Надання методу `CheckCollision()` для перевірки перетину з іншим колайдером.
    *   Прапорець `IsTrigger` для "м'яких" колізій (без фізичної реакції).
*   **Використання**: Додається до `GameObject`, який повинен мати фізичну форму для зіткнень.

## 5. Графічна Система (Graphics/)

*   **`Engine::Graphics::Renderer2D`**: Статичний клас, що надає інтерфейс для малювання 2D-примітивів (квадратів, спрайтів). Він абстрагує деталі OpenGL.
*   **`Engine::Graphics::OrthographicCamera`**: Визначає область світу, яку видно на екрані.
*   **`Engine::Scene::SpriteRenderer`**: Компонент, який додається до `GameObject` і відповідає за його візуалізацію як кольорового квадрата.

---

## 6. Система Вводу (EngineCore/Input.h)

*   **`Engine::Input`**: Статичний клас, що надає простий інтерфейс для перевірки стану клавіш (`IsKeyPressed()`). Він абстрагує ввід від GLFW.

---

## 7. Ігровий Цикл (Game Loop)

1.  **`Engine::Application::Run()`**: Запускає нескінченний цикл.
2.  **Розрахунок `deltaTime`**: Визначається час, що минув з попереднього кадру, для плавної анімації.
3.  **`Application::OnUpdate(deltaTime)`**: Викликається метод оновлення клієнтської гри.
    *   `GameApp::OnUpdate()` викликає `m_Scene->OnUpdate(deltaTime)`.
    *   `Scene::OnUpdate()` викликає `GameObject::OnUpdate(deltaTime)` для кожного об'єкта.
    *   `GameObject::OnUpdate()` викликає `Component::OnUpdate(deltaTime)` для кожного свого компонента (наприклад, `RigidBody2D`, `PlayerController`).
4.  **`Application::OnRender()`**: Викликається метод рендерингу клієнтської гри.
    *   `GameApp::OnRender()` налаштовує `Renderer2D` та викликає `m_Scene->OnRender()`.
    *   `Scene::OnRender()` викликає `GameObject::OnRender()` для кожного об'єкта.
    *   `GameObject::OnRender()` викликає `Component::OnRender()` для кожного свого візуального компонента (наприклад, `SpriteRenderer`).
5.  **Оновлення вікна**: `m_Window->OnUpdate()` обробляє події вікна та обмінює буфери.

## 8. Використані Сторонні Бібліотеки (EngineLibraries/)

*   **GLFW (Graphics Library Framework)**:
    *   **Призначення**: Створення вікна, керування контекстом OpenGL, обробка вводу (клавіатура, миша).
    *   **Роль у проєкті**: Надає низькорівневу функціональність для взаємодії з операційною системою та графічним процесором.
*   **GLAD (GL Loader Generator)**:
    *   **Призначення**: Завантаження функцій OpenGL. OpenGL — це лише специфікація, а GLAD надає вказівники на реальні функції драйвера відеокарти.
    *   **Роль у проєкті**: Дозволяє використовувати сучасні функції OpenGL.
*   **GLM (OpenGL Mathematics)**:
    *   **Призначення**: Математична бібліотека, оптимізована для використання з OpenGL. Надає класи для векторів, матриць, кватерніонів тощо.
    *   **Роль у проєкті**: Використовується для всіх математичних операцій, пов'язаних з графікою та фізикою (позиції, масштаби, трансформації, обчислення колізій).
*   **ImGui (Immediate Mode GUI)**:
    *   **Призначення**: Бібліотека для створення швидких та простих інтерфейсів користувача (наприклад, для дебагу, інструментів розробника).
    *   **Роль у проєкті**: Може бути використана для створення внутрішньоігрових інструментів або дебаг-інтерфейсів.
